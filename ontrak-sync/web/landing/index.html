Know what every host is behind on — and install only what a person approved.

Ontrak Sync walks each host on the Network, then every container on it, and asks apt, snap and the container registries what is behind. Findings land in one dashboard; applying them is a decision an operator makes, not a side effect of a scan.

Why Ontrak Sync

A fleet that reads “0 pending” while three hosts have been unreachable for a month.

“No updates” and “I could not look” are not the same answer

A target that could not be read is Unknown, shown next to the pending count — never a zero that looks like a clean bill of health.

An update tool must not become an outage

No dist-upgrade, no installs, no removals, no config-file replacement, and no blind container recreate. Each is a setting that is simply not offered.

The registry budget is shared with every pull

A fetched image digest is reused for six hours, so two scans in an afternoon cost one pass of requests instead of turning an update into 429.

What it is

One service, one dashboard, every host on the LAN.

Two modes, one of them deliberate

detect scans and waits. auto installs inside a window and scope chosen in the settings form — with security_only as what makes it tolerable.

Unknown is a first-class state

Not installed here → no finding, not an error. Could not look → no finding, an error recorded. Neither ever expires a finding it did not check.
