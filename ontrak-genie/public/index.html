        skills & memory
        

          
        

      

      

        


        
        

          
            
what this workspace remembers

          
          

        


        

          
            
add one from GitHub

          
          

            
          

          

            A skill is a markdown playbook from a public GitHub repository, and it
            is installed into your account on this deployment — the lane
            that sits above the shared one and below this project's own
            .genie/skills, so nothing here changes what
            anybody else is offered. For a skill the whole deployment should have,
            an operator runs genie skills add <owner/repo>.
          

        


        

          
            
skills on offer

          
          

          

            The model sees that menu at the start of every turn and loads a playbook
            when one fits the work. A skill kept in
            .genie/skills travels with the code, so
            everyone who clones this workspace gets it.
          

        

      

    


    
    

      

        remote workspaces
        

          
        

      

      

        


        
        

          
            
a folder on a server, over SSH

          
          

            
            
            
            
            
            
            
          

          

            
          

          

            The folder is mounted inside the sandbox and becomes where the agent works, so its edits
            land on the server and the preview runs the project there. Nothing is written into the
            workspace: a password is handed to the mount and never written to disk, and a key is kept
            for this session only and removed when you disconnect.
          

        


        

          
            
a repository on GitHub

          
          

            
            
            
          

          

            
            
            
            
          

          

            The clone lands in the working directory and is edited in place, so the app can be previewed
            as it changes. The token is supplied per git command and never written into
            .git/config.
          

        


        

          
            
Atlas — the ecosystem's forge

          
          

          

            
            
            
            
            
          

          

            
            
            
            
            
            
            
            
          

          

            Atlas is an optional add-on — a subscription, or this deployment's own credential, is what grants it. These
            are the Gitea endpoints, so any Gitea forge works here. A project created or cloned here becomes where the
            agent works, so it can be run and previewed straight away.
